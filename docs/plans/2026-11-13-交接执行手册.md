**项目背景**：心迹是基于 Open-LLM-VTuber 的心理陪伴数字人，已进入 AIC2026"AI+心理健康"赛道国赛。后端为 Python（FastAPI + WebSocket），前端为 React（`frontend-src/`）。核心代码在 `src/open_llm_vtuber/mental_health/` 和 `src/open_llm_vtuber/agent/agents/mental_health_agent.py`。

**Git**：

- 每个任务单独提交一次，提交信息用中文，格式 `类型: 摘要`。
- 不要把 `conf.yaml`、`mental_health_memory/`、`chat_history/`、`output/`、`work/`、`private/`、`models/` 加入提交。
- 磁盘上残留的 `.github/workflows/` 4 个未跟踪文件和 `.learnings/` 不要提交，也不要删除。

**验证命令**（Windows PowerShell，仓库根目录）：

```powershell

.\.venv\Scripts\python.exe -m unittest discover -s tests        # 当前基线：174 项全部通过
.\.venv\Scripts\ruff.exe check src/open_llm_vtuber tests scripts

cd frontend-src; node --test tests/; npm run build:web; cd ..
```

注意：`.venv` 里没有 pytest，请用 `unittest`。前端测试是 `node:test` 写的 `.cjs` 文件，用 `typescript` 包现场转译 TSX，写法参考 `frontend-src/tests/companion-trend.test.cjs`。

**设计原则（不要违反）**：
1. 安全优先：Safety 输入检查必须在任何模型调用之前完成。高风险输入走固定回复，不调用 Dialogue 或 Decision 模型。任何新增的模型层只能**升级**风险，不能降级。
2. 未知不等于零：没有观测的维度保持 `null`/未观测，不要填 0。
3. 模型输出不可信：模型返回的 JSON 必须严格校验，失败时回退到规则实现，并在 `decision_trace` 记录回退原因。
4. 不记录原文：日志和状态记录不写用户原话（现有代码一直遵守这一点）。
5. 每项新行为都要有单元测试；改动不能让现有 174 项测试失败。
6. 不宣称疗效，不做诊断。

**完成后汇报**：改了哪些文件、新增了哪些测试、验证命令的实际输出、仍未解决的问题。

## 任务 2：流式输出 + 逐句安全检查，降低首句时延（P0，2～3 天）

**问题**：`mental_health_agent.py` 的 `chat_with_safety()`（约第 350～406 行）先收齐整段生成结果，再做 `check_output`，之后才 `yield`。实测 p95 为 13.84 s，还要再加上 TTS 时间。

**步骤**：
1. 先阅读 `agent/transformers.py` 中的 `sentence_divider`，弄清它如何把字符串流切成句子。目标是改成"边生成边切句、逐句检查、通过即 yield"。
2. 推荐实现：在 `chat_with_safety` 内部维护缓冲区；每凑满一个完整句子（以 。！？!?\n 结尾，或缓冲超过 60 字），就对这一句调用 `self._safety_guard.check_output(sentence)`：
   - `ALLOW`：立即 `yield` 这一句。
   - `REWRITE`：`yield` 改写后的句子。
   - `BLOCK`：停止消费模型流，`yield` 固定的阻断回复，后续内容全部丢弃，`decision_trace` 记 `output_safety_override=True` 和原因码 `output_safety_block_midstream`。
3. 流结束后，对**完整回复**再做一次 `check_output`，作为跨句模式的补充检查。如果此时才命中，后面的内容已经播出，无法撤回：只在 trace 中记 `late_output_flag`，**不要**重复播放。在 trace 里如实记录这种情况。
4. 写入聊天记录（`_add_message`）和状态（`_store_state`）的内容，必须是**实际发出的句子**的拼接。
5. `protocol_redirect` 分支（`boundary.control_only`）不需要模型生成，保持原样，可以提前判断后直接返回。
6. 在配置中加入开关 `mental_health_agent.streaming_output: bool`（默认 `true`），保留旧的整段模式，方便对照。配置类在 `config_manager/agent.py`，两份默认模板 `config_templates/conf.default.yaml` 和 `conf.ZH.default.yaml` 都要更新（见 CLAUDE.md 的约定）。
7. 可选：在等待首句期间，下发一次 `Actions(motion="gentle_nod")`，让数字人表现出正在倾听。

**测试**：
- 模拟 Dialogue 流（参考 `tests/test_mental_health_agent.py` 中现有的假客户端）：第一句正常、第二句有害 → 只输出第一句加阻断回复，且第二句之后的 token 不再被消费。
- 正常三句 → 逐句产出，内容与整段模式一致。
- 关闭开关 → 行为与旧版完全一致，原有测试不需要修改。
- 写一个时延测试：用假流模拟每个 token 延迟 50 ms，断言第一句的 yield 早于流结束。

**验收**：在真实 ORPO 服务下测 10 轮，记录首句出现时间（从收到输入到第一句 yield），p50 < 2.5 s。把结果写入 `docs/mental_health_streaming_latency.md`。

## 任务 3：用模型做状态与意图抽取（P0，4～6 天，算法核心）

**问题**：
- `state_estimator.py` 用关键词计数打分，每维只有 0/0.35/0.7/1.0 四档，并有子串误命中（如"累"命中"积累"）。
- `intent_estimator.py` 用整句 `re.fullmatch`，"能不能给我点建议""我该怎么办"等自然说法识别不了。

**步骤**：
1. **先建评测集**，再写代码。新建 `tests/fixtures/state_intent_eval.json`，300 条以上中文用户句。字段：
   `text`、`stress|anxiety|low_mood`（0～1 或 null，null 表示没有表达这一维）、`intent`（venting / seeking_practical_help / seeking_clarification / ending / small_talk / other）、`advice_preference`（declined / requested / unspecified）、`split`（dev / holdout）。
   覆盖面：否定（"不累"）、他人（"我朋友很焦虑"）、过去时、反问、口语和网络用语、长句混合多个意图。全部用虚构内容。
   需要两个人独立标注。标注表模板放在 `docs/evaluation/state_intent_annotation.md`，由人工完成。AI 只能起草候选标签，并标为 `draft`。
2. 新建 `src/open_llm_vtuber/mental_health/llm_estimator.py`，提供 `LLMStateIntentEstimator`：
   - 调用一个 OpenAI 兼容接口（复用 `decision_client.py` 的写法：`AsyncOpenAI`、`max_retries=0`、`asyncio.wait_for` 超时、严格 JSON 解析，拒绝重复键和附加正文）。
   - 输出 schema：`{stress, anxiety, low_mood: float|null, self_current: bool, intent, advice_preference, feedback: helpful|unhelpful|unspecified}`。用 Pydantic 严格校验。
   - 返回类型与现有接口一致：`estimate()` 返回 `PsychologicalState`（`estimator_source="llm_v1"`，`observed_dimensions` 只包含非 null 的维度）；意图转换为现有的 `InteractionIntent`。
   - **安全约束**：`risk_level` 永远取自 Safety 结果，模型不能修改。
   - 失败或超时时回退到 `ContextStateEstimator` 和 `IntentEstimator`，并在 state 中标记回退原因。
   - 规则的明确命中优先：如果规则 `IntentEstimator` 给出 `certainty="explicit"`，以规则结果为准。这样旧测试的语义不变。
3. 在 `long_term.py` 的 `observation_source()` 映射中加入 `"llm_v1": "system_estimate"`。
4. 配置：`mental_health_agent.estimator: rule | llm`（默认 `rule`，保证向后兼容），并配置 endpoint/model。在 `agent_factory.py` 中按配置组装。可以复用已部署的 ORPO 4B 服务（端口 8000），也可以使用独立的 Decision 1.5B 服务。
5. **评测脚本** `scripts/evaluate_state_intent.py`：在 dev/holdout 上分别计算规则版和模型版的各维 MAE、"是否观测"的 F1、意图准确率和宏 F1、建议偏好准确率，输出 JSON 和 Markdown 到 `docs/mental_health_state_intent_eval.md`。结果必须注明是"开发者构建的虚构句库"。
6. **校准实验**（放进同一脚本或单独脚本）：从 SQLite 中取同一天既有 `system_estimate` 又有 `user_report` 的维度，计算 Pearson/Spearman 相关和平均偏差。这需要试用数据，没有数据时脚本应明确报告"样本不足"，不能编造数字。

**测试**：JSON 校验失败、超时、缺字段、越界值时都回退；模型声称低风险不能覆盖 Safety；null 维度不进入 `observed_dimensions`；配置为 `rule` 时行为与现在一致。

**验收**：holdout 上模型版的意图宏 F1 和维度"是否观测" F1 均高于规则版；评测报告已生成；174 项旧测试和新测试全部通过。

**目标**：把"多智能体"讲清楚。Safety、State、Intent、Decision 各自给出带依据的提议，由协调器按固定优先级仲裁，前端显示"本轮为什么这样回应"。

**步骤**：
1. 在 `schemas.py` 的 `CoordinationTrace` 中新增 `proposals: list[AgentProposal]`。每个 `AgentProposal` 包含 `role`（safety / state / intent / feedback / history / decision_model）、`suggested_strategy | null`、`evidence_codes`、`confidence: low|medium|high|null`。只记录代码和标签，不记录原文。
