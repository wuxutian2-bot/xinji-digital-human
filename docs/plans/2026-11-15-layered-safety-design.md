# 任务六：可选第二层输入安全判断

依据交接手册任务六执行。先冻结新增合成样例，再运行真实模型比较；默认配置保持第二层关闭。

采用组合包装器：先执行既有规则，高风险、阻断或改写立即返回；其余结果交给独立、严格 JSON 分类器。合并结果取更高风险，输出固定安全回复，模型不生成危机回应。输出安全检查仍由既有逐句规则执行。相比扩写关键词，此方案能够另行验证语义补充效果；相比用模型替换规则，此方案保留即时规则处理和确定性回退。

分类器只接收当前发言与上一轮安全等级、动作，不读取聊天原文历史。模型响应限定风险枚举及有限证据码。拒绝附加正文、重复 JSON 键、未知字段、截断响应及不一致证据。超时、接口错误和无效输出保留规则动作、等级及固定回复，结构化追踪记录原因码、耗时和升级状态。取消信号继续向上传播。

实施顺序：

1. 扩充 `context_safety_cases.json` 的 `holdout_v3`，原80条对象及标签保持一致；新清单保存原样例摘要、新夹具摘要和实际比较源码摘要。原清单保留为历史记录。
2. 新增 `llm_safety.py`，接入配置、工厂、关闭资源与结构化追踪；两份默认模板同步关闭开关。
3. 新增严格解析、风险单调性、超时和取消、上下文、输出透传、工厂配置与实际 Agent 危机旁路测试。
4. 扩展原评测脚本，分别记录原规则、上下文规则和分层版的误报、漏报、回退与调用耗时。用本机模型完成真实比较，保留模型、提示摘要与夹具来源；不把模拟输出或人工草拟标签称为独立盲测。
5. 全量后端测试、Ruff、前端类型检查、前端测试与构建后，更新手册与报告，任务六单独本地提交。

统计验收看 `holdout_v3` 的漏报是否为零或明显减少，并同时报告误报；不通过时如实保留差距，不改测试标签迎合模型。所有样例是虚构工程标签，尚无独立临床审核，不据此宣称疗效或生产安全保证。
