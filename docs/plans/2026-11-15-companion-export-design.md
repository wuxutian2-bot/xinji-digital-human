# 任务七：档案缓存、批量播放查询与导出

依据交接手册任务七实施，保持现有本机单档案边界。

1. `companion_for()` 优先复用 Agent 的 CompanionStore；缓存须仍绑定同一个 memory 实例和同一服务端 user_id。切换数据库、用户或退出 SQLite 模式时更新或清除缓存。API 使用该统一解析器，避免每次请求重复建表。
2. 每批 turns 先取记录，再以精确的片段回执ID一次批量读取 playback；使用 SQLite json_each 传递一个JSON参数，避免片段数量导致绑定变量超限。保持缺回执、失败、静默片段和中断的既有语义。导出复用播放状态组装逻辑。
3. 新增只读 `GET /api/companion/export`，在同一SQLite读事务中读取当前服务端用户的全部 states、turns、actions，turns包含嵌套播放回执状态。不使用列表接口的100/1000条上限，不读取其他用户、配置密钥或原始聊天历史。下载JSON附带版本、时间、user_id和示例标记，设置固定安全文件名、attachment、no-store和nosniff。
4. “数据与隐私”页新增“导出我的数据”，说明导出范围；示例档案标明导出虚构记录。下载直接请求完整导出接口，不从页面缓存拼装。失败时显示错误，不把错误响应保存为数据；下载对象URL使用后释放。
5. 验证实例复用与档案切换、固定SQL查询次数、播放语义、超过页面上限仍完整导出、两用户同ID隔离、下载头和本机来源边界；前端覆盖按钮及成功/失败下载。以独立合成档案核对真实浏览器下载和手机布局，完成后更新手册并单独本地提交任务七。

选择Agent局部缓存，便于跟随现有生命周期；不使用进程全局缓存，避免跨档案复用。选择一致性快照直接导出，避免多次翻页读取期间出现跨表状态偏差。现有本机来源中间件继续限制来源，不把本次改动扩展为公网账户系统。
