# 心迹逐句安全检查与首句时延

2026-11-14，在 Windows、NVIDIA GeForce RTX 5060（8 GB）上实测。

## 测量口径

每组在独立临时 SQLite 数据库中，从空历史开始，按同一顺序连续进行 10 轮虚构的课堂展示对话。通过项目的 AgentFactory 加载本机角色提示词、规则决策、上下文安全检查和 TTS 文本预处理。ORPO 对话模型温度为 0.7。计时从提交文字输入开始，分别记录首个非空模型文本片段、首个含可朗读文本的 SentenceOutput 和整轮生成完成的时间。语音合成、网络下发和浏览器播放在计时范围之外。模型目录查询和 Agent 初始化在首轮计时前完成。

## 安全行为与回归

默认启用 `mental_health_agent.streaming_output`。每个完整句子或达到上限的片段先过输出检查。命中改写时只发改写文本，命中阻断时关闭模型流并发送固定回复。对已发文本的完整复查若发现跨句风险，只记录 `late_output_flag`。已经送出的句子无法撤回。聊天上下文按实际输出拼接，心理状态与决策追踪仅保存结构化信息。危机输入仍走生成前的固定响应，纯协议控制请求沿用原整段检查和本地重定向逻辑。

新增回归覆盖 50 毫秒模拟 token 的提前输出、中途阻断和关闭上游、跨句命中与改写、60 字边界、换行、表情与思考标签、空响应、中断、反馈回执以及关闭开关后的整段行为。后端 192 项和前端 15 项测试通过。Ruff 检查与格式检查通过，网页生产构建成功。

## 复测

默认 ORPO 服务可用时，在仓库根目录运行以下命令。脚本验证本地端点和模型名，每轮打印三个时间点，仅使用临时会话。

```powershell
.\.venv\Scripts\python.exe scripts/benchmark_streaming_latency.py --mode streaming
.\.venv\Scripts\python.exe scripts/benchmark_streaming_latency.py --mode buffered
```

本机也准备了一份合并 ORPO 适配器的 Q4_K_M 权重，保存在 Git 忽略的 `models/dialogue/mental-health-orpo-q4_k_m.gguf`（2,497,278,784 字节）。源适配器 SHA-256 为 `870fb58d685ad4a9f16d4644b321176dd0f5569b5758f09bd3b9922078742ca5`。用 PEFT 合并到 BF16 基座后，通过 llama.cpp b10964 转换并量化，最终 GGUF SHA-256 为 `4882d33b0f19fd86de223aaa3accd1b868a0e5d7878115df5cbfba442db781b6`。

在本机复测这份权重时，先将 Ollama 的 `OLLAMA_HOST` 设为 `127.0.0.1:18082` 并启动 `ollama serve`。在第二个 PowerShell 窗口运行下列命令。模板使用 Qwen 的对话分隔符和 8192 token 上下文。应用也可以通过 `mental_health_agent.dialogue.base_url` 和 `model` 接入这个兼容端点。

```powershell
$env:OLLAMA_HOST = '127.0.0.1:18082'
ollama create mental-health-orpo -f config_templates/mental_health_orpo.Modelfile
.\.venv\Scripts\python.exe scripts/benchmark_streaming_latency.py --base-url http://127.0.0.1:18082/v1
```
