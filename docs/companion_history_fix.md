# 2026-10-02：日常入口与历史会话修订

## 原因与修复

个人服务与合成演示服务使用不同端口和档案。演示页面不会读取个人聊天；个人服务未运行时，停留在演示页面会造成“原历史消失”的误解。日常入口使用个人配置的服务地址，本机为 `http://localhost:12393/`；`12401` 仅在另行启动合成演示时使用。

原有连接流程每次刷新都新建聊天，读取历史列表时又仅改变前端选中 ID，没有同步加载消息。现改为先读取当前服务档案的历史：恢复本标签页上次选中的有效会话，否则加载最新会话；没有已保存会话时才创建。选择按服务地址和档案分别记录，外部档案的 ID 不会直接用于恢复。普通列表刷新只更新列表，不切换当前会话。

读取历史不再自动删除空会话文件。删除由明确操作触发，经界面确认，收到服务端成功回执后才移除列表项。旧会话文件不迁移、不改写；演示与个人档案继续隔离。

## 日常界面

- 顶部保留带文字的「聊天记录／新聊天」和「设置」。移除群聊、模式切换入口。
- 移除摄像头、屏幕、浏览器面板及没有行为的附件按钮。
- 设置突出「显示／语音」，连接参数与开发选项折叠到高级区域。
- 历史列表区分个人、试用和示例档案；未保留文本的体验档案明确提示。中文界面使用中文相对时间。
- 移除重复的新建／加载成功提示条，避免遮挡窄屏工具栏；保留错误提示。
- 启动麦克风遵守已有的自动开启选项，默认不开启。

## 验证

174 项后端测试、10 项前端专项测试及 Web 构建通过。新增测试覆盖旧会话恢复、失效或其他档案 ID 回退、空列表创建和读取时不删除空会话。完整 TypeScript 检查仍存在 585 项既有诊断，按文件和错误内容比对无新增诊断。

在个人页面验证了历史列表、载入较早会话、刷新后恢复原选中会话、新建空聊天后打开历史列表不改变当前会话、精简设置入口。原会话文件哈希全部保持一致。另以独立固定问候验证了现有模型服务，没有向历史写入该检查内容。

这次检查只证明历史读取、界面与服务可运行，不替代真人语音与主观体验验收。私人历史备份、校验明细和含档案信息的截图保留在 Git 忽略的 `private/`，不进入提交包。
