# 成年同学本机体验手册

状态：待组织真实参与。本文件是执行材料，不是已完成的需求或效果报告。建议邀请 8～15 位成年同学，先访谈 5 位；2～3 天后邀请回访，实际返回人数照实记录。不通过本工具自动发送邀请。

## 操作者准备

1. 冻结代码版本及配置摘要，完成 [功能验收](companion_acceptance.md)。每人创建独立配置，先用合成档案演练。
2. 告知用途、所用服务、保留内容、退出及删除方式；不要求分享真实困扰，不收姓名、学号或联系方式进研究记录。成年人确认与参与同意分开核对，聊天文本保留另行选择。
3. 只在受试者愿意的情况下记录匿名原话。若内容可识别本人，先征求其确认再去除识别信息。参与者可跳过、撤回或停止。
4. 不以合成历史假扮参与者经历。历史纠正任务使用「合成演示」档案；本人自报只在其独立真实档案记录。操作员在验证备注里说明使用了哪个档案。

界面入口：参与者从「我的心迹 → 看变化 → 查看与修改记录」完成纠正任务。数据选择位于面板底部「数据与隐私」。操作者使用 `/?view=demo` 的演示工作台核对档案，并在「组织者工具」中按实际情况记录到访或回访；这部分不要求参与者操作。

## 首轮访谈：开放提问

- 你在什么情况下希望有人先听，而不是给建议？
- 什么样的建议或追问会让你觉得不被理解？
- 如果系统记错了你的感受，你希望如何查看、纠正或删除？
- 对保存聊天原文、状态趋势、小步骤，你分别能接受什么？
- 你希望下次回来时系统记得什么，又不希望它记得什么？

匿名原话 → 需求类别 → 对应功能 → 验证结果，四栏一起填。不能把研发者推断写成访谈原话。没有得到的需求保持空白。

## 统一任务与成功标准

| 任务 | 给参与者的说明 | 观察标准 |
|---|---|---|
| 倾诉 | 表达“先听我说”，可用按钮或文字 | 能设置倾诉偏好，回应避免直接布置行动 |
| 切换求助 | 改为希望一起想办法；随后对回答选择没帮助 | 偏好同步；下一轮先澄清，可取消反馈 |
| 纠正记录 | 在合成档案查看一条状态，纠正一个维度 | 来源改变、趋势重算；其他维度和未知值不被填充 |
| 保存行动 | 从求助回答手动保存一条小步骤 | 确认后保存；重载仍可见；完成/跳过有区别 |
| 打断并恢复 | 实际麦克风输入，播放中打断，再继续两轮 | 输入被识别；旧音频和动作停止；后续回复可播放，回到空闲 |

任务结果用 `independent`（独立完成）、`assisted`（经帮助完成）、`failed`（未完成）；未执行用 null。记录秒数和具体失败原因，区分自动化、操作者和参与者的观察。真人语音任务应在真实服务执行，离线文字演示不能代替。

## 同一套 1～5 分问题

每题可以不答。1＝非常不同意，2＝不同意，3＝一般，4＝同意，5＝非常同意。

1. 被理解感：这次交流让我觉得自己的意思被理解了。
2. 偏好被尊重：系统尊重了我想倾诉、梳理或求助的选择。
3. 记忆控制感：我知道系统记下了什么，也能控制纠正或删除。

开放题：哪一点没有帮助，或让你不舒服？下次还愿意用吗，为什么？不要只摘正面回答。

## 回访

2～3 天后用原档案再次打开，回顾同一个小步骤。记录邀请回访人数和实际返回人数；没有返回不补值。已完成不等于有帮助，跳过也不等于失败。记录行动数量、帮助/没帮助反馈，不能换算为心理状态改善。

## 数据填写与汇总

```powershell
.\.venv\Scripts\python.exe scripts/trial_evidence.py prepare --file private/trials/study.json --count 10 --version companion-2026-10-01
# 体验后按实际观察编辑 study.json；null 保持为缺失，不填模拟结果。
.\.venv\Scripts\python.exe scripts/trial_evidence.py summarize --file private/trials/study.json --output output/AIC2026/trial-summary.json
```

工具拒绝重复参与编号、合成数据标记、未经同意的已参与记录和不可能的回访关系。汇总不输出原话，只输出实际人数、任务独立/协助/失败/缺失、耗时样本数、问卷均值及其样本数、1～2 分反馈数量。提交时再将经许可的匿名原话整理为需求追踪表。

最终报告须列出版本、招募方式、实际人数、退出与缺失、负面反馈、操作者帮助和网络/设备故障。结论只涵盖原型可用性及主观体验，不写临床疗效、因果改善或总体人群结论。
